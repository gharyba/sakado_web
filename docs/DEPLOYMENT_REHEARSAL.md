# Deployment rehearsal — Phase 07

This is local, synthetic, non-deploying tooling. No external target is accepted by `test:staging`; the original database is not read, reset, migrated or restored. Execute only from the intended repository on Node 24 with a reviewed production build.

The runner creates `.local/phase07/run-<random>/postgres`, storage, a synthetic dump and a safe report. All are Git-ignored. PostgreSQL listens only on loopback 55438; application on loopback 3127. Occupied ports are refused, never reused/killed. Generated test credentials are ephemeral, passed privately to child processes and never printed or committed. Existing .env DB values are ignored/overridden. Child application processes are stopped and the owned cluster shut down in cleanup; the restored disposable database is dropped after successful verification. Only the created synthetic object is removed. Logs are captured privately for assertions and not echoed; safe evidence contains counts/hashes/statuses only.

Before migrations, provisioning, backup/restore or cleanup, the runner checks its exact generated URL, expected database/user and PostgreSQL's **actual data directory** against its newly created cluster. It does not accept an arbitrary backup target. `--pg-bin` identifies existing compatible pg_dump/pg_restore tools, not a server. `--rollback-dir` identifies a reviewed built source copy, not a remote host. No generic destructive database command is exposed.

## Startup and failure behavior

Supported launcher validates production environment before spawning Next; a missing build exits 1, and hostname overrides are rejected. `npm start` stays loopback. Hostinger's command uses 0.0.0.0 and process PORT; actual managed routing is untested. Do not bypass the launcher to silence failed bootstrap/configuration checks.

The rehearsal verifies operational health, demo health without DB, safe unavailable-DB 503, invalid setting failures, missing build, headers, staging robots/sitemap, route protection, generated media restart hash, storage failure with no new gallery row, first-owner duplicate protection, complete backup/restore and optional previous-artifact switch. Invalid startup configuration exits before HTTP service exists; it is not claimed to return an HTTP 503 from a server that never starts. The health handler separately returns 503 when operational configuration/connectivity fails at request time.

Existing Phase 05/06 suites cover actual login/logout, session expiry, roles, event draft/edit/publication/cancellation, registration validation/idempotency/capacity/status changes, CSV escaping/authorization and admin form behavior. Contact smoke is safe route rendering plus existing validation; do not send real messages or contact third parties. Instagram source links/imported records remain untouched; only synthetic test records may be exercised in guarded clusters. No scraping/download or API expansion.

## Performance and release inventory

Offline preflight inventories public paths/sizes/SHA-256, duplicate hashes, lockfile/schema/migration hashes, build ID, runtime, source commit when explicitly supplied, registry counts and outstanding issues. It never inserts test PASS results it did not execute; `sourceState` remains unverified when uncommitted changes are possible. Runtime credentials, .env, personal data, dumps, signed evidence and original library files are excluded.

Before release record exact commit/dirty state, build time/ID, Node/platform, locked dependencies, migration status against the approved target, media approval snapshot/hash, backup/restore evidence reference, real CI URLs/results, smoke/device/accessibility results and rollback artifact/owner. A HEAD SHA alone does not identify uncommitted code. No release package or remote upload is generated by preflight.

Check homepage/event HTML and JS transfers, deferred animation chunks, LCP elements, raster optimization endpoint, cache behavior and large/unknown assets. The local swatch and small demo illustrations do not represent real scenic images or slow devices. Preserve optimization limits/rights gates. External staging must profile approved media on representative devices; no arbitrary Lighthouse score is a release substitute.
