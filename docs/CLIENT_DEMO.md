## Open the preview

From the repository root, on Node 24:

```powershell
npm run dev:client
```

Open **http://localhost:3000** after `npm run dev:client`. It prepares derivatives and starts the existing Next development server on `127.0.0.1:3000`. Stop with Ctrl+C. It does not edit `.env`, connect to PostgreSQL, authenticate to a provider, deploy or upload anything. An explicitly production/staging process is refused. Do not expose this development server through tunnels, proxies, port forwarding or a LAN listener. Normal development now uses `npm run dev` with the existing local PostgreSQL configuration.

Phase 09 adds a separate safe company demo: `$env:DEMO_MODE='true'; npm run dev`. This selects wordmark/initials/illustrations, confirmed company facts and explicitly illustrative listings; it clears `DATABASE_URL`, `CLIENT_DEMO` and the private directory in the child process. It does not prepare or serve private photos. See [PHASE_09](PHASE_09.md). Neither preview grants public media permission. Earlier validation counts below are historical; Phase 09 records its own reruns.

The equivalent manual Next development setup is:

```powershell
npm run prepare:client
$env:CLIENT_DEMO = 'true'
$env:CLIENT_DEMO_DIRECTORY = (Resolve-Path '.local/client-preview').Path
$env:DEMO_MODE = 'true'
$env:DATABASE_URL = ''
$env:SITE_URL = ''
$env:ADMIN_URL = ''
$env:STAGING_MODE = 'false'
npm run dev:app
```

Use a new local terminal, and close it afterward so these process settings do not affect unrelated commands. `CLIENT_DEMO_DIRECTORY` is a server-only runtime path, restricted to the exact workspace `.local/client-preview` directory. Never prefix these settings with `NEXT_PUBLIC_`, add them to deployment templates or start the preview against a configured database. Normal development and production behavior remain in place when the explicit preview conditions are absent.
